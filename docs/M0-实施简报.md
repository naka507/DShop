## 1. M0 交付清单（`docs/10` §12.1 / §12.3）

1. **D1 schema 41 表**（一次迁移建全，含二期才点亮的表）。

4. **服务令牌体系**：签发 / 校验 / scope / 吊销 / 轮换。
5. **`maskAgentPayload()`** 单一出口脱敏。

7. **后台登录 + RBAC 骨架**。
8. **`data/seed-cs/`**：`products.json`、`product_attrs.json`、`aftersale_policies.json`、`orders.json`、`aftersales.json`、`users.json`、`seed_cs.sql`。
9. **OpenAPI 导出**：`docs/agent-api.openapi.json`（CI 生成 + 契约快照）。
10. **契约版本化**：`X-Contract-Version` 头。

## 3. 数据模型（`docs/05` §5.1–§5.4）

### 3.1 统一约定（§5.3）

| 项 | 约定 |
| --- | --- |
| 主键 | **ULID 字符串（26 位，时间有序）**，例 `01J9Z8K2M4N5P6Q7R8S9T0V1W2` |
| 金额 | **整数，单位「分」**，列名后缀 `_amount` |
| 比例 | **万分比**，列名后缀 `_bp`（如 `commission_rate_bp`） |
| 列名 | snake_case；JSON 响应 camelCase |
| 时间 | **ISO-8601 字符串，UTC**（`YYYY-MM-DDTHH:mm:ss.sssZ`） |
| 删除 | 软删除用 `status` 枚举，**不做物理删除** |
| 库存 | `stock` 物理库存、`locked_stock` 已锁未付；**可售 = `stock - locked_stock`** |

### 3.2 41 张表清单（§5.1，按域分组）

- **商户（3）**：`merchants`、`stores`★、`store_stocks`
- **商品（5）**：`categories`、`products`★、`product_skus`★、`product_attrs`★、`product_images`
- **交易（8）**：`cart_items`、`orders`★、`sub_orders`★、`order_items`★、`order_status_logs`★、`payments`、`refunds`、`idempotency_keys`
- **售后（3）**：`aftersales`★、`aftersale_logs`★、`aftersale_policies`★

### 3.3 关键表字段（§5.2 文档给出的全部内容）

> ⚠️ **文档没有给出 CREATE TABLE、字段类型、NOT NULL/DEFAULT/CHECK、ON DELETE**。
> 下列字段是文档给出的全部；未列出的字段（含 `id`、`created_at`、`updated_at`）**文档未定义**，
> 由实现侧按 §3.1 统一约定补齐，并在 README「文档未定义项」登记。

- `users`：`phone`（唯一，**加密存储**）、`nickname`、`avatar_url`、`status`、`wechat_openid`（预留）
- `merchants`：`type(self/vendor/branch)`、`name`、`logo_url`、联系方式、资质图片、`status(pending/approved/suspended/rejected)`、`commission_rate_bp`、收款账户
- `stores`：`merchant_id`、`name`、`type(warehouse/store)`、经纬度、地址、营业时间、`supports_pickup`、`status`
- `categories`：`parent_id` 树形、`name`、`sort_order`、`status`
- `products`：`merchant_id`、`category_id`、标题/副标题/主图、`detail_html`、`brand`、`status(draft/pending_review/onsale/offsale/rejected)`
- `product_skus`：`product_id`、`spec`(jsonb)、`sku_code`、`price`、`stock`、`locked_stock`、`restock_eta`（可空，**SKU 级**）、`status(active/inactive)`
- `product_attrs`：`spu_id`、`group_name`、`attr_name`、`attr_value`、`unit`、`sort_order`、`searchable`
- `orders`：`order_no`（唯一，`^DS\d{17}$`）、`user_id`、`status`、`total_amount`、`discount_amount`、`freight_amount`、`pay_amount`、`address_snapshot`(jsonb)、`coupon_id`、`channel(web/miniprogram/app)`、`pay_deadline`、支付/完成时间
- `sub_orders`：`sub_order_no`（唯一，`{orderNo}-{2位}`）、`order_id`、`merchant_id`、`store_id`、`status`、`subtotal`、`discount_alloc`、`freight`、`commission_amount`、`express_company`、`express_no`、`shipped_at`、`settled`
- `order_items`：`sub_order_id`、`sku_id`、商品快照（`title`/`image`/`spec`/`unit_price`）、`quantity`、`subtotal`
- **`order_status_logs`（物流轨迹与状态时间线的落库处）**：`from`/`to`、操作者类型/ID、备注、时间。Agent `/orders/{orderNo}` 的 `express.traces` 与状态时间来源
- `aftersales`：`aftersale_no`（唯一，`^AS\d{11}$`）、`sub_order_id`、`user_id`、`type(refund_only/return_refund)`、`status`、`reason`、`evidence_urls`(jsonb)、`refund_amount`、`return_express_no`、`deadline_at`
- `aftersale_logs`：文档仅说明「售后状态流转与操作者记录（客服介入留痕）」；API 需要 `at`/`actor`/`from`/`to`/`remark`
- `aftersale_policies`：`category(return/refund/exchange/freight/warranty)`、`title`、`content`(markdown)、`version`、`effective_from`、`effective_to`、`status(draft/effective/archived)`
- `service_tokens`：`token_hash`（HMAC-SHA256）、`token_prefix`、`name`、`scopes`(jsonb)、`status`、`expires_at`、`last_used_at`、`rate_limit_per_min`、`created_by`
- `agent_call_logs`：`token_id`、`path`、`params_hash`、`status`、`duration_ms`、`cache_hit`、`contract_version`、`created_at`
- `roles`：`scope(platform/merchant)`、`code`、`name`、`permissions`(jsonb 权限点数组)
- `admin_user_roles`：后台账号 ↔ 角色
- `merchant_members`：`merchant_id` + `admin_user_id` + 角色(owner/manager/staff)

**RBAC 表说明**：**没有** `permissions` / `role_permissions` / `user_roles` 表。权限点以 jsonb 数组存在 `roles.permissions`。

### 3.5 库存原子更新（§5.3② 逐字照录）

下单**只锁定**：`UPDATE product_skus SET locked_stock = locked_stock + ? WHERE id = ? AND stock - locked_stock >= ?`
支付成功**实扣**：`UPDATE product_skus SET stock = stock - ?, locked_stock = locked_stock - ? WHERE id = ?`
超时/取消**只释放**：`UPDATE product_skus SET locked_stock = locked_stock - ? WHERE id = ?`

> ⚠️ **禁止**下单时同时减 `stock` 与加 `locked_stock`（可售虚减 2q）。

### 3.6 单号规则（§5.3⑤ 定案）

| 单号 | 格式 | 正则 | 规则 | 例 |
| --- | --- | --- | --- | --- |
| `order_no` | `DS`+17 位数字 | `^DS\d{17}$` | 14 位秒级 `YYYYMMDDHHmmss`（**UTC+8**）+ 3 位当秒序列 `001`–`999` | `DS20260920143000123` |
| `sub_order_no` | 主单号+`-`+2 位 | `^DS\d{17}-\d{2}$` | 主单下自增，从 `01` 起 | `DS20260920143000123-01` |
| `aftersale_no` | `AS`+11 位 | `^AS\d{11}$` | 8 位 `YYYYMMDD`（UTC+8）+ 3 位当日序列 | `AS20260922001` |
| `pay_no` | `PAY`+17 位 | `^PAY\d{17}$` | 同主单号规则 | `PAY20260920143100001` |
| `refund_no` | `RF`+17 位 | `^RF\d{17}$` | 同主单号规则 | `RF20260922030100001` |

> ⚠️ **时区**：单号内嵌时间戳是 **UTC+8**，而时间字段是 **UTC**。
> `DS2026**0920143000**0123` ⇔ `2026-09-20T**06:30**:00.000Z`。生成单号须先转 UTC+8 再格式化。
> ⚠️ **前缀**：`seed.md` 用 `ORD`，**以 `DS`/`AS` 为准**，seed-cs/fixture 必须同步改。

### 3.7 枚举（§5.2 / §7）

- 主单 `orders.status`：`PENDING_PAYMENT`/`PAID`/`SHIPPED`/`COMPLETED`/`CANCELLED`
  **由子单聚合得出，不单独维护**（聚合优先级见 §5）
- 子单 `sub_orders.status`：`PAID`/`SHIPPED`/`COMPLETED`/`CANCELLED`
- 售后 `aftersales.status`：`PENDING_MERCHANT`/`WAIT_BUYER_RETURN`/`BUYER_RETURNED`/`MERCHANT_RECEIVED`/`REFUNDING`/`REFUNDED`/`REJECTED`/`CANCELLED`；`type`：`refund_only`/`return_refund`
- 政策：`category`=`return`/`refund`/`exchange`/`freight`/`warranty`；`status`=`draft`/`effective`/`archived`
- 商品：`products.status`=`draft`/`pending_review`/`onsale`/`offsale`/`rejected`；`product_skus.status`=`active`/`inactive`
- 商户：`merchants.type`=`self`/`vendor`/`branch`，`status`=`pending`/`approved`/`suspended`/`rejected`；`stores.type`=`warehouse`/`store`
- 其他：`task_queue.status`=`pending`/`processing`/`done`/`failed`；`user_coupons.status`=`unused`/`used`/`expired`；`settlements.status`=`pending`/`confirmed`/`paid`；`orders.channel`=`web`/`miniprogram`/`app`；`payments.channel`=`wechat`/`alipay`

**⚠️ 文档未定义**：`payments.status`、`refunds.status`（仅 §8.2 出现小写 "payments→paid"、§7.5 示例 `"PENDING"`）、`admin_users.status`、`users.status`。已在 `packages/shared/src/enums.ts` 末尾补齐并标注。

### 3.8 二期才点亮的表（§11.2 / §5.4）

## 4. Agent API 契约（`docs/07`）

### 4.1 统一响应与错误码（§7.1）

响应体 `{ code, message, data }`；成功 `code: 0` + `message: "ok"`。

| code | HTTP | 含义 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败 |
| 40010 | 400 | 不支持的契约版本（**显式提供才报**） |
| 40101 | 401 | 服务令牌缺失或无效 |
| 40102 | 401 | 服务令牌已吊销或已过期 |
| 40301 | 403 | 令牌 scope 不含该资源 |
| 40401 | 404 | 订单不存在 |
| 40402 | 404 | 商品不存在或已删除 |
| 40403 | 404 | 售后单不存在 |
| 40404 | 404 | 政策分类无生效条款 |
| 40501 | 405 | 对 Agent 组使用了非 GET |
| 40901 | 409 | 受控写幂等冲突或状态不允许 |
| 42901 | 429 | 触发限流 |
| 50001 | 500 | 服务内部错误 |

### 4.2 六端点

| # | 端点 | scope | 限流（/min，burst 20） | 边缘缓存 |
| --- | --- | --- | --- | --- |
| 7.2 | `GET /api/v1/agent/orders/{orderNo}` | `agent:order:read` | 120 | 10s |
| 7.3 | `GET /api/v1/agent/orders` | `agent:order:read` | 120 | 10s |
| 7.4 | `GET /api/v1/agent/products/{spuId}/specs` | `agent:product:read` | 300 | 60s |
| 7.5 | `GET /api/v1/agent/products/{spuId}/stock` | `agent:product:read` | 300 | 30s |
| 7.6 | `GET /api/v1/agent/aftersales/{aftersaleNo}` | `agent:aftersale:read` | 120 | 10s |
| 7.7 | `GET /api/v1/agent/policies/{category}` | `agent:policy:read` | 60 | 300s |

**`/orders` 查询参数**（§7.3）：`userId`（ULID）/ `phone`（11 位）**二选一**（同时缺失或同时提供 → `40001`）、`status`（多值逗号分隔）、`limit`（默认 5，1–20）、`cursor`。
响应含 `userId`、`list[]`、`nextCursor`、`hasMore`。缓存 key = `agent:orders:{userId}:{status}:{limit}:{cursor}`，响应带 `X-Cache`。

**`/orders/{orderNo}` 响应**（§7.2）：`orderNo`、`status`、`statusText`、`channel`、`createdAt`、`paidAt`、`payAmount`、`currency`、`receiver`（脱敏）、`subOrders[]`（`subOrderNo`/`merchantName`/`merchantType`/`status`/`statusText`/`shipFrom`/`express`/`items[]`）、`aftersaleSummary`（`hasAftersale`/`openCount`/`refundedAmount`）。
**主单与子单状态必须同时下发**（§8.3）。

**`/products/{spuId}/specs` 响应**（§7.4）：`spuId`、`title`、`subtitle`、`brand`、`categoryPath[]`、`status`、`mainImage`、`updatedAt`、`contentHash`、`attrGroups[]`（`groupName`/`attrs[]`）、`specDimensions[]`、`skus[]`（**不含 stock 数值**，仅 `inStock`）。

**`/products/{spuId}/stock` 响应**（§7.5）：`spuId`、`status`、`checkQuantity`、`available`、`totalStock`、`updatedAt`、`shipFrom[]`、`skus[]`（含 `stock` 可售值、`inStock`、`restockEta` **SKU 级**）。
查询参数：`skuId`、`quantity`（默认 1）、`regionCode`（**预留**）。
`available` = 目标数量 ≤ 可售库存；**客服话术应优先依据 `available`**。

**`/aftersales/{aftersaleNo}` 响应**（§7.6）：`aftersaleNo`、`type`、`typeText`、`status`、`statusText`、`orderNo`、`subOrderNo`、`skuId`、`itemTitle`、`quantity`、`refundAmount`、`currency`、`reason`、`evidenceCount`（**仅计数**）、`createdAt`、`deadlineAt`、`returnAddress`（脱敏，`WAIT_BUYER_RETURN` 起有值）、`returnExpress`、`refund{status,refundNo,channel,arrivedAt,estimatedArrivalDays}`、`timeline[]`、`policy`。
**每次流转必须写 `aftersale_logs`**（timeline 唯一来源）。

**`/policies/{category}` 响应**（§7.7）：`category`、`contentHash`、`items[]`（`policyId`/`title`/`version`/`effectiveFrom`/`effectiveTo`/`updatedAt`/`content` markdown/`tags[]`）。
路径参数 `category` 支持五类 + `all`。

### 4.3 服务令牌（§7.8.1）

- 格式：`dshop_svc_<24 位随机 base62>_<6 位校验位>`；**明文仅创建时返回一次**
- 传输头：`X-Service-Token`（**非 Bearer**，**不允许**放 query string）
- 存储：`token_hash = HMAC-SHA256(AGENT_TOKEN_PEPPER, token)`；`token_prefix` 存**前 16 位**
- scope（一期四个读）：`agent:order:read`、`agent:product:read`、`agent:aftersale:read`、`agent:policy:read`
- 默认有效期 **180 天**，到期前 30 天 Cron 告警；`rate_limit_per_min` 默认 **600**
- 签发：`POST /api/v1/admin/agent-tokens`，权限点 `agent:token:manage`，**强制 TOTP 二次确认** + 落审计
- 轮换：**双令牌并行**，旧令牌设 `expires_at` 宽限期 **7 天**；`POST /admin/agent-tokens/:id/revoke` 立即吊销
- 可选加固：`AGENT_SIGN_SECRET`，待签串 `HMAC-SHA256(AGENT_SIGN_SECRET, timestamp + method + path + query)`，头 `X-Timestamp` + `X-Signature`，偏离 > **300s** 拒绝；开关 `settings.agent_require_signature` **默认关闭**

### 4.4 脱敏器 `maskAgentPayload()`（§7.8.2）

| 字段 | 规则 | 示例 |
| --- | --- | --- |
| 手机号 | 保留前 3 后 4 | `138****8888` |
| 固定电话 | 保留区号 | `0571****0000` |
| 姓名 | 姓氏 + `**` | `张**` |
| 收货地址 | 仅省/市/区 + `***` | `浙江省 杭州市 西湖区 ***` |
| 退货地址 | 同上 | — |
| 快递员电话 | **不下发** | — |
| 物流单号 / 订单号 / 售后单号 | **完整下发** | `SF1234567890123` |
| 用户 ID | 完整下发（26 位 ULID） | `01J9Z8K2M4...` |

**绝不下发清单**：`password_hash`、`wechat_openid`/`unionid`、`raw_callback`、支付渠道密钥、`cost_price`、供应商信息、`address_snapshot` 原文、售后凭证图 URL、后台账号信息。§7.4 另禁 `cost_price`/供应商/采购价/内部备注；§7.6 `evidence_urls` 不下发仅 `evidenceCount`。
**作用范围**：Agent 组**所有响应必须经此单一出口**；以 Zod `.strip()` **白名单**模式运行（白名单外字段一律丢弃）。

### 4.5 只读保证（§7.8.3 四重）

1. Agent 路由组**只挂 GET**；非 GET → `405` + `40501`（`agentReadOnlyGuard`）
2. 令牌 scope 校验
3. 中间件链不含写路径
4. **CI 用 `no-restricted-imports` 拦截** Agent 组 import 写 API

## 5. 核心业务流程（`docs/08`）

### 5.1 下单（§8.2）

`POST /shop/orders` 带 `Idempotency-Key`；`DB.batch` 原子批次 = **只锁定库存** + 写主单/子单/order_items 快照/状态日志；任一 SKU `changes=0` → `400 ORDER_STOCK_NOT_ENOUGH` 整批回滚。
支付回调验签 + `channel_trade_no` 唯一约束幂等 → 锁定转实扣、主单 `PAID`、子单 `PAID`。
**商品快照在下单瞬间固化**。

### 5.2 主单状态聚合（§8.3）

**主单状态恒由子单聚合，不单独维护**；**聚合前先剔除 `CANCELLED` 子单**：
1. 全部 `CANCELLED` → `CANCELLED`
2. 剔除后全部 `COMPLETED` → `COMPLETED`
3. 剔除后全部 ∈ {`SHIPPED`,`COMPLETED`} 且至少一个 `SHIPPED` → `SHIPPED`
4. 其余 → `PAID`

优惠券与运费在主单层计算后**按子单 `subtotal` 比例分摊**写入 `discount_alloc`。
部分退款只置该子单 `CANCELLED`，退款金额级联到 `aftersaleSummary.refundedAmount`，**不把主单置 `CANCELLED`**。
每次流转写 `order_status_logs`。

### 5.3 售后流程（§8.4）

申请（仅退款/退货退款）→ `PENDING_MERCHANT`（同意/驳回，超时未处理自动同意）
- 仅退款：同意 → `REFUNDING` → 渠道退款 → 回调 → `REFUNDED`
- 退货退款：同意 → `WAIT_BUYER_RETURN`（**下发退货地址**）→ 用户回寄填单号 → `BUYER_RETURNED` → 商家确认收货 → `MERCHANT_RECEIVED` → `REFUNDING` → `REFUNDED`

平台客服可全程介入改判；全程落 `aftersale_logs` + `audit_logs`。售后可发生在 `PAID` 之后任意状态。

### 5.4 政策发布（§7.7 / M0 交付）

平台后台 `POST /api/v1/admin/aftersale-policies`，权限点 `aftersale:policy:manage`，落 `audit_logs`，
发布后**主动失效 `/policies/*` 边缘缓存**。这是 PiEcho 政策语料的唯一维护入口。

### 5.5 物流轨迹同步（§8.6）

Cron **每小时**拉取在途子单轨迹落库（写 `order_status_logs`），供 `/orders/{orderNo}` 的 `express.traces` 读取；
非实时直连快递商，`latestStatusAt` 表明新鲜度。

## 6. 认证与 RBAC（`docs/09`）

### 6.1 JWT（§9.1）

- **HS256（WebCrypto）**，密钥 `JWT_SECRET`（**32 字节随机**）
- Payload：`sub` / `aud`(shop·admin·merchant) / `role` / `mid`(商户)
- **强隔离**：`shop` Token 访问 `/admin/*` → `401`；`admin` Token 访问 `/merchant/*` → `401`；用户 JWT 访问 `/agent/*` → `401`；Agent 令牌访问非 `/agent` 路由 → `401`
- Cookie：**HttpOnly + Secure + SameSite=Lax**；三入口域名独立
- Access Token **2h**；Refresh Token **14d**，随机串，D1 存哈希，**旋转式**（每次刷新作废旧 token）
- 登录：C 端手机号+短信验证码（60s 冷却、图形验证码、按 IP/手机号限流）；后台用户名+密码+TOTP；**连续失败 5 次锁定 15 分钟**
- CSRF：同源策略 + `Origin` 头校验中间件（仅 Cookie 模式）

**⚠️ 文档未定义**：Cookie 名称与 Domain/Path 显式值、刷新端点路径、JWT 的 `iat/exp/nbf/jti`、签发端点。

### 6.2 密码哈希（§11.1）

- **PBKDF2-SHA256，10 万次迭代**，WebCrypto 原生（无 WASM），封装在 `packages/auth` 单点
- 存储格式**带算法前缀 `pbkdf2$...`**（`admin_users.password_hash`）
- TOTP：`admin_users.totp_secret` / `totp_enabled`；**平台管理员强制，商户管理员可选**；签发 Agent 令牌强制 TOTP

**⚠️ 文档未定义**：salt 长度、派生密钥长度、`pbkdf2$` 内部字段拼接、TOTP 算法/位数/步长/恢复码。

### 6.3 RBAC（§9.2）

权限点命名 **`域:动作`**：`merchant:approve`、`product:review`、`order:ship`、`aftersale:approve`、`settlement:confirm`、`agent:token:manage`、`aftersale:policy:manage`。

**8 角色**：
1. 顾客
2. 平台超管（全部，含 `agent:token:manage`）
3. 平台运营（类目/商品审核/营销/内容位/**政策发布**）
4. 平台财务（结算确认/对账/退款复核）
5. 平台客服（订单查询/售后介入，**不可**改商品与资金配置）
6. 商户管理员（本商户全部）
7. 商户店员（发货/售后处理，**无**改价与店员管理）
8. **PiEcho Agent 服务身份**（`/agent/*` 只读，无任何写权限）

中间件链：`requestId → accessLog → rateLimit → auth(aud|serviceToken) → rbac(perm) → merchantScope → zodValidator → handler`
商户行级隔离由 `merchantScope` 强制注入 `merchant_id = 当前商户`；**Agent 组不走 `merchantScope`**，走令牌 scope。
后台所有写操作落 `audit_logs`。

| --- | --- |
| `/api/v1/shop/*` | C 端 |
| `/api/v1/admin/*` | 平台后台 |

### 7.4 售后政策（`seed.md` §1）

覆盖 `return`/`refund`/`freight`/`warranty` 四值。

**① 7 天无理由退货 → `return`**

- **买家承担**：个人主观原因（听感不习惯、不喜欢外观颜色、重复拍错）；未与客服沟通擅自寄回导致的拒收二次派送费用

**③ 维修与质保（非人为损坏）→ `warranty`**
- 旗舰电子类产品自签收之日起 **1 年官方全国联保**
