> 与 eshop 的工程纪律对齐点及仍存差异。相关设计文档见 `docs/03-工程结构与前端.md` §3、

## 13.1 代码格式（Prettier）

根目录新增 `.prettierrc.json`，与现有代码风格一致：

| 选项                   | 取值          | 说明                               |
| ---------------------- | ------------- | ---------------------------------- |
| `semi`                 | `true`        | 语句末尾保留分号                   |
| `singleQuote`          | `false`       | 使用**双引号**（现有代码即双引号） |
| `tabWidth` / `useTabs` | `2` / `false` | 2 空格缩进                         |
| `printWidth`           | `100`         | 单行 100 列                        |
| `trailingComma`        | `"all"`       | 多行结构补尾逗号                   |
| `endOfLine`            | `"lf"`        | 统一 LF（避免 Windows CRLF 混入）  |

`.prettierignore` 排除：`node_modules`、`dist`、`build`、`.wrangler`、`.turbo`、
`data/`、`*.sql`（迁移是手写 DDL，**不应被格式化**）、`package-lock.json`。

**建议命令**（当前未在根 `package.json` 增加 `format` script，避免与其他并行改动冲突）：

```bash
npx prettier --write .    # 格式化
npx prettier --check .    # 仅校验（CI 可用）
```

> ⚠️ 本次**未实际运行** `prettier --write .`，以免重写大量文件与并行工作冲突。
> 首次全量格式化建议在独立提交中完成，并单独评审 diff。

## 13.2 本地环境变量与 secret 注入

`apps/api/.dev.vars.example` 列出本地开发所需绑定（字段名取自 `apps/api/src/env.ts` 的 `Env`）：

- `JWT_SECRET`、`AGENT_TOKEN_PEPPER`、`PHONE_ENC_KEY`、`PHONE_HASH_PEPPER`（必填 secret）
- `ENVIRONMENT`（`development` / `staging` / `production`）
- `AGENT_REQUIRE_SIGNATURE`（可选，默认关闭）

值一律是**明显的占位符**（如 `dev-insecure-secret-change-in-production`），不是真实密钥。

使用方式：

1. `cp apps/api/.dev.vars.example apps/api/.dev.vars` 后替换为本地随机值；
2. `.dev.vars` 已被根 `.gitignore` 忽略（`.gitignore` 第 17 行，注释「环境变量（只提交 .dev.vars.example）」），**绝不提交**；
3. 生产不写 `.dev.vars`，改用 `wrangler secret put <NAME> --config apps/api/wrangler.jsonc` 注入
   （见 `docs/09-认证权限与部署.md` §10）。

> **仍缺：自定义域 / 路由**。三个 Worker 目前只有 `*.workers.dev` 默认域名，
> 未配置 `routes`，故 `docs/09` §10.2 提到的平台后台 / 商户后台**独立域名分流**
> 尚未生效（hostname 分流逻辑已在客户端就绪，但需要绑定真实域名才能触发）。
> 接正式域名需补 `routes` 并准备相应 DNS 记录。

**形态说明**：两个前端都是纯客户端 SPA（React 19 + react-router `BrowserRouter`，无 SSR），
因此各自采用「**薄 Worker + Workers Assets**」形态，而非把静态资源直接当 Worker 上传：

1. `assets.directory: ./dist`、`assets.binding: ASSETS` —— 静态产物由 Workers Assets 托管；
2. `assets.not_found_handling: single-page-application` —— 深层链接刷新回退 `index.html`，
   交给前端路由，避免 404；
3. `assets.run_worker_first: ["/api/*"]` —— **只有** `/api/*` 先经过 Worker，其余请求直接由
   Assets 处理，省一跳；
4. `services: [{ binding: "API", service: "dshop-api" }]` —— Worker 内用 `env.API.fetch(request)`
   同源反代到 API Worker。**必须用 Service Binding 而非公网 `fetch`**（免公网往返与出网计费、
   不依赖 API 对外域名），见 `docs/12-eshop架构对齐审计.md` §12.3.4「必须照抄的硬知识」。

这与前端 `src/api/transport.ts` / `src/api/client.ts` 强制使用相对路径 `/api/v1/*` 的设计
互为闭环：开发期由 Vite 代理转发，生产期由本 Worker 同源反代，前端代码无需感知环境差异。

> 注：`docs/09-认证权限与部署.md` §10 承诺的 `npm run deploy`（= `turbo run deploy`：
> api → storefront → admin）依赖各 workspace 存在 `deploy` script。三个 app 均已具备，
> 且**均可实际部署**。

> ⚠️ 首次部署顺序：必须先部署 `apps/api`（`dshop-api`），否则两个前端的 Service Binding
> 指向的 Worker 尚不存在，`deploy` 会因绑定校验失败。注意 `turbo.json` 目前**只**定义了
> `build` / `typecheck` / `test` / `lint` 四个任务，**没有** `deploy` 任务，故 `turbo run deploy`
> 只是并发跑各 workspace 的 `deploy` script，**不保证** api → storefront → admin 的顺序。
> 首次部署请显式按序执行：
>
> ```bash
> npm run deploy --workspace=@dshop/api
> npm run deploy --workspace=@dshop/storefront
> npm run deploy --workspace=@dshop/admin
> ```

## 13.4 CI 步骤清单

`.github/workflows/ci.yml` 的 `gates` job 步骤（保持原有顺序，末尾追加部署 dry-run）：

| 步骤                         | 作用                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 检出                         | `actions/checkout@v4`                                                                                                                                                                                                                                                                                |
| 安装 Node                    | `actions/setup-node@v4`，Node 24，启用 npm 缓存                                                                                                                                                                                                                                                      |
| 安装依赖                     | `npm ci`                                                                                                                                                                                                                                                                                             |
| 类型检查                     | `npm run typecheck`（turbo run typecheck）                                                                                                                                                                                                                                                           |
| 单元测试                     | `npm test`（turbo run test）                                                                                                                                                                                                                                                                         |
| 静态检查                     | `npm run lint`（turbo run lint）                                                                                                                                                                                                                                                                     |
| 前端构建                     | `npm run build`（turbo run build）                                                                                                                                                                                                                                                                   |
| 契约自检                     | `npm run check`（`scripts/check.ts`，OpenAPI 与字段契约一致性）                                                                                                                                                                                                                                      |
| **部署 dry-run（apps/api）** | `working-directory: apps/api` 下 `npx wrangler deploy --dry-run --env=""`（顶层环境）+ 循环 `preview` / `staging` / `production` 各跑一次。**不限制分支**（PR 上同样拦截配置错误），`continue-on-error: false`。`--dry-run` 不需要 `CLOUDFLARE_API_TOKEN`，故无需注入 secret。`--env=""` 是必需的：`wrangler.jsonc` 含 `env` 多环境段，不显式指定会触发「Multiple environments are defined…」警告；多环境段的绑定集合互不继承，故必须逐个跑 |
| **部署 dry-run（apps/storefront）** | `working-directory: apps/storefront` 下 `npx wrangler deploy --dry-run --config wrangler.jsonc`，验证前端 `wrangler.jsonc` 的 assets 目录与 `API` / `ASSETS` 绑定可解析。前端配置**无** `env` 多环境段，故**不需要** `--env=""`。不限制分支、`continue-on-error: false` |
| **部署 dry-run（apps/admin）** | 同上一行，`working-directory: apps/admin` |

## 13.5 与 eshop 的对齐点与仍存差异

**已对齐**：

- Prettier 代码格式化（配置项与建议命令）；
- 本地 `.dev.vars.example` + 生产 `wrangler secret put` 的 secret 注入纪律；
- 每个 app 具备 `deploy` / `deploy:dry` script，部署命令统一为 wrangler；
- CI 包含类型检查 / 单测 / 静态检查 / 构建 / 契约自检 + 部署 dry-run 门禁。

**仍存差异**（eshop → DShop）：

| 维度     | eshop      | DShop                                                                          | 说明                                                |
| -------- | ---------- | ------------------------------------------------------------------------------ | --------------------------------------------------- |
| 包管理   | pnpm       | npm workspaces                                                                 | 见根 `package.json`（`packageManager: npm@12.0.2`） |
| 构建编排 | turbo      | 根 `package.json` 使用 `turbo run *`，但 DShop 当前**未配置 turbo 流水线缓存** | 依赖 `turbo` 二进制，缓存/任务图待补                |
| 格式化   | prettier   | prettier（本次新增配置）                                                       | 配置已对齐，尚未全量跑                              |
| E2E      | Playwright | **无**                                                                         | DShop 目前无端到端测试                              |
